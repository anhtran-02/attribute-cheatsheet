👥Ai làm gì?
👤 BU / PO
→Xác định use case & tiêu chí lọc
→Tư vấn DA về yêu cầu dữ liệu
→Tạo segment từ attribute (hoặc cách khác)
→Dùng segment trong journey/promo/widget/ads
📊 DA
→Thiết kế loại attribute phù hợp
→Chuẩn bị BQ table + pipeline
→Pre-check & validate trước submit
→Submit trên Athena UI
→Xử lý lỗi data / segment sai
🛡️ Segment Admin
→Review & approve attribute mới (Thứ 3 & Thứ 5)
→Trigger sync data (Tag use cases)
→Support DA khi gặp vấn đề pipeline / config
→Tư vấn thiết kế attribute cho edge cases
⚠️ Segment sai ≠ luôn do hệ thống
trace: BU demand → DA logic → DA data → Sync
❌Lỗi hay gặp (DA)
✗ attributeNameId trong BQ không khớp với Attribute ID trên UI (case-sensitive)
✗ Dùng Multiple Tag khi user chỉ giữ 1 tag tại một thời điểm
⚠ Timestamp dùng giờ/phút → dùng TIMESTAMP_TRUNC(..., DAY)
🔗Cần lọc theo nhiều tag trong 1 attribute?
1 Dùng AND nhiều attribute — tạo nhiều attribute riêng lẻ, rồi AND lại khi build segment trên Athena. Ưu tiên thử cách này trước.
2 Concat thành 1 tag — nếu AND không serve được use case, DA concat các tag lại thành 1 giá trị duy nhất (VD: vietcombank_gold).
? Vẫn chưa giải quyết được? Liên hệ tuong.nguyen2 để được hỗ trợ.

Ghi rõ tên dự án, mục tiêu, logic tính — để admin review và BU sau này dễ dùng
③ Data đến từ đâu?
field: Source
→
Batch BQ/Airflow — DA setup  |  Streaming realtime — BE setup
④ Tính toán thế nào?
field: Aggregation Type
→
Nhãn mới nhất → MOST_RECENT
Nhãn mới nhất trong N ngày → MOST_RECENT_WDR
Tổng / đếm / số ngày → AGGREGATION_WDR
⑤ BU lọc theo gì?
field: Integration Level
→
Chỉ lọc theo nhãn → TAG_ID
Lọc theo ngưỡng số → PARTIAL_VALUE_BY_TAG
Nhãn + ngưỡng số → PARTIAL_VALUE_BY_TAG
⑥ Nhãn có quản lý trước?
field: Tag Management
→
Có sẵn & <50 nhãn → Predefined Tag — khai báo ở Tag Info
Nhãn "vô vàn" / động → Dynamic Tag
⑦ User giữ nhiều tag cùng lúc?
field: Attribute Type
→
Không (tag mới thay tag cũ) → Single Tag (tier, KYC)
Có (tích lũy nhiều tag) → Multiple Tag (banks used, gifts)
⚠️ Một số tổ hợp chưa support trên UI:
PARTIAL_VALUE_BY_TAG + Single Tag Multiple Tag + Single Tag MOST_RECENT_WDR + Single Tag
Và một vài trường hợp chưa hiện trên UI cũng không support. Nếu nhu cầu chưa được hệ thống support → liên hệ anh.tran17.

📐DA Pre-Submit Checklist ⚠️ Chỉ áp dụng cho TAG — hay lỗi pipeline
☑ Column names đúng: agentId, attributeGroup, attributeNameId, timestamp, tagsAdd
☑ Timestamp là Unix milliseconds (13 chữ số) + TIMESTAMP_TRUNC(..., DAY)
☑ attributeNameId trong BQ khớp chính xác với Attribute ID trên Athena (case-sensitive)
☑ DISTINCT date ≤ 180; không có nhiều timestamp khác nhau trong cùng 1 ngày
☑ Predefined tags: mọi giá trị tagsAdd đã có trong danh sách Athena
▶ DA tự call function check sau khi submit attribute (TAG):
CALL `momovn-prod.REPORT.ATTRIBUTE_PRECHECK_DATA_CONFIG`(
  'momovn-mds-shared.REWARD_STORE.rewards_athena_...',  -- p_table_name
  'user_project_reward_transaction_users',             -- p_attributenameid (case-sensitive)
  ['project_rewards_burn_expire_coin', 'churned', ...]  -- p_tag_list_on_athena
);
⚡ 180-day limit: Data > 180 ngày bị bỏ qua. Lifetime use cases → dùng snapshot pattern: rebuild bảng mỗi ngày với timestamp = hôm qua
